# منصة تصاريح دخول الميدان — ميدان سيد الشهداء

منصة موحدة تغطي دورة التصريح كاملة: التقديم، والاعتماد على مرحلتين، وإصدار تصريح إلكتروني برمز QR، والتحقق الميداني من الحالة الفعلية في النظام.

## التشغيل

```bash
npm install
npm run dev
```

ثم افتح http://localhost:3000

- بدون `DATABASE_URL` تعمل المنصة على PostgreSQL مدمجة (PGlite) في المجلد `data/`.
- للإنتاج: اضبط `DATABASE_URL=postgres://...` و `PUBLIC_BASE_URL=https://النطاق-الرسمي`.
- المرفقات تُحفظ في `storage/` خارج المجلد العام.

## مختبر الصلاحيات (`/sandbox`)

استخدم النظام الحقيقي بنفسك في الأدوار الستة: ممثل جهة، مراجع أولي، معتمد نهائي، متحقق ميداني، مشرف الميدان، مسؤول النظام.

1. **جهّز السيناريو** بنقرة: طلبات لجهات مختلفة في كل المسارات، وطلب معاد لجهتك، وآخر بانتظار الاعتماد النهائي، وتصاريح سارية وموقوفة، ونشاط بوابات في الساعات الماضية، وحجوزات قادمة تُشعل توقع الازدحام في مركز القيادة.
2. **اختر دورك** — ويظهر في كل شاشة **شريط المختبر العائم**: تبديل الدور بلمسة، ومهام الدور تُعلَّم تلقائيًا من سجل العمليات، وجوال ممثل جهتك برسائله ورموزه، ورموز جاهزة لاختبار البوابة (ساري، موقوف، مزيف).

يعمل فقط في وضع التجربة الداخلية، وكل بياناته تجريبية.

## المحاكاة الحية «عِش التجربة» (`/demo`)

رحلة تفاعلية من 7 فصول يلعب فيها الزائر كل الأدوار خلال 3 دقائق تقريبًا — وكل خطوة تُنفَّذ على النظام الحقيقي:

1. **الطلب** — ممثل جهة، النموذج يملأ نفسه ويتحقق، ثم تقديم حقيقي برقم مرجعي ورسالة نصية تظهر كإشعار.
2. **المراجعة** — شاشة المراجع بدرجة المخاطر المحسوبة فعليًا وأسبابها.
3. **الاعتماد** — اعتماد نهائي، مع إثبات أن المراجع نفسه يُمنع من المرحلة الثانية، ثم إصدار واحتفال ذهبي.
4. **البطاقة** — بطاقة الجوال الحقيقية برمز يتغير كل 30 ثانية.
5. **البوابة** — مسح الرمز الحي، مطابقة الأفراد والمركبات، رمز الممثل يصل كإشعار، ثم السماح بالدخول.
6. **التحايل** — صورة شاشة قديمة ورمز مزيف، ويرفضهما النظام.
7. **الختام** — شهادة بمدة الرحلة وبصمات SHA-256 لكل عملية من سجل العمليات، مع روابط للشاشات الحقيقية.

**نسخة مستقلة للعرض والمشاركة:** [simulation/index.html](simulation/index.html) — ملف واحد يُفتح بالنقر المزدوج دون خادم ودون تثبيت (الشعار مضمّن داخله، والبصمات SHA-256 تُحسب فعليًا في المتصفح). مناسب للإرسال للعميل أو العرض في اجتماع. البيانات فيه محاكاة داخل المتصفح ولا تصل للنظام.

نسخة `/demo` داخل النظام تعمل فقط في **وضع التجربة الداخلية**، وتفتح جلسات الحسابات التجريبية دون كلمة مرور. إيقاف وضع التجربة من الإعدادات يعطّلها تلقائيًا قبل الإطلاق.

## التطبيق على الجوال (PWA)

- يُثبَّت من المتصفح كتطبيق حقيقي: أيقونة على الشاشة الرئيسية، ملء الشاشة، شاشة إطلاق، واختصارات (طلب جديد، التحقق، العمليات).
- يبدأ من `/start` الذي يفتح الواجهة المناسبة لكل مستخدم تلقائيًا.
- على الجوال: شريط تبويب سفلي، وورقة «المزيد»، واهتزاز خفيف عند اللمس (أندرويد)، وانتقالات بين الصفحات، واحترام الحواف الآمنة.
- دون اتصال: بوابة التحقق وبطاقة الممثل تعملان بعد فتحهما مرة واحدة، وباقي الصفحات تعرض `/offline`. تُمسح الصفحات الشخصية من الذاكرة عند تسجيل الخروج.
- عامل الخدمة (`public/sw.js`) يعمل في نسخة الإنتاج فقط (`npm run build && npm start`) وعلى **HTTPS** أو `localhost`.
- لتجربته على جوالك قبل النطاق الرسمي استخدم نفقًا آمنًا مثل `npx cloudflared tunnel --url http://localhost:3000` ثم افتح الرابط من الجوال واختر «إضافة إلى الشاشة الرئيسية».

## المظهر الليلي والنهاري

كل الألوان تمر عبر رموز موحّدة في `src/app/globals.css`، والمظهر الليلي يبدّل الرموز فقط، فأي صفحة جديدة تدعم المظهرين تلقائيًا. التفاصيل في [`THEME.md`](THEME.md).

- `npm run check:theme`: يشتغل تلقائيًا قبل كل بناء ويوقفه لو فيه لون ثابت يتجاوز الرموز.
- `npm run audit:theme`: يكتشف كل الصفحات بنفسه ويقيس تباين كل نص بالمظهرين على الجوال والكمبيوتر.

## قبل الإطلاق

1. ربط بوابة الرسائل النصية في `src/lib/notify.ts` وإيقاف وضع التجربة من الإعدادات.
2. نقل قاعدة البيانات إلى PostgreSQL دائمة، والمرفقات إلى تخزين دائم، ونسخ احتياطي.
3. نطاق رسمي بشهادة HTTPS (مطلوب لتوليد الرمز المتغير في متصفح الجوال وللكاميرا).
4. مراجعة أمنية واختبار اختراق من الجهة المختصة.
